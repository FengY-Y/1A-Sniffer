## 2. 环境：为什么选虚拟机，而不是 WSL2

### 2.1 结论先说

**用 VMware Workstation（或 VirtualBox）装 Ubuntu Desktop 虚拟机做实验主体；WSL2 可以留着写代码、跑单元测试。**

### 2.2 关键差异

| 维度 | VirtualBox/VMware 虚拟机 | WSL2 |
|---|---|---|
| 能抓到的流量 | 取决于虚拟网卡：NAT 只有自己；**桥接/内部网络 + 混杂模式**能抓到同网段其他主机 | 默认 NAT：**只能看到 WSL 自己的流量**；看不到 Windows 主机和其他机器的单播流量 |
| 混杂模式（promiscuous） | 虚拟网卡可设「全部允许」，配合 ARP 欺骗可以做中间人演示 | 基本没有意义，vNIC 拿不到不属于自己的帧 |
| ARP 欺骗 / MITM 演示 | 可以做，且能随时打快照回滚 | 做不了（不在同一广播域，且会影响主机网络） |
| 内核模块 / netfilter / eBPF | 可以做，和真机一致 | 内核是微软定制的，**不能随便加载自己编译的模块** |
| GUI | 完整桌面，Qt/GTK 随便跑，录屏方便 | 有 WSLg，但窗口、输入法、录屏都更容易出问题 |
| 快照/回滚 | 一键快照，实验炸了 10 秒还原 | 没有 |
| 资源开销 | 需要 4 GB 内存、20 GB 磁盘、开 VT-x | 更轻 |

一句话：**WSL2 的默认网络模型决定了它只能"看见自己"，而嗅探器实验的价值恰恰在于"看见别人"。** 文档 p14 要求"深入理解抓包层次与分析层次"，你在 WSL2 里连"为什么抓不到别人的包"都演示不了。

> WSL2 唯一值得考虑的场景：Windows 11 22H2 以上开 `networkingMode=mirrored`，可以镜像主机网卡、抓到主机流量。但它对混杂模式、ARP、内核模块的支持仍然不完整，且容易和 VPN/防火墙打架。**不要把它当主力环境。**

### 2.3 虚拟机怎么配（VMware Workstation，你手上这套）

#### 2.3.0 先确认三件事

1. 版本：`帮助 → 关于`，17.x 即可（17.5 之后个人使用免费）。
2. 虚拟化：任务管理器 → 性能 → CPU，右下角"虚拟化：已启用"。
3. **没有 Hyper-V 抢占**（见 2.3.1，这一步最容易踩坑）。

#### 2.3.1 先处理 Hyper-V（很关键）

```powershell
# 管理员 PowerShell
systeminfo | Select-String "Hyper-V"
bcdedit /enum "{current}" | Select-String hypervisorlaunchtype
```

出现 `A hypervisor has been detected...` 或 `hypervisorlaunchtype Auto`，说明 WSL2 / Docker Desktop / 内核隔离 正在占用 Hyper-V。这时 VMware 会退到 **ULM 兼容模式**：性能腰斩、3D 和某些设备异常，抓包本身还能用，但演示时界面会明显卡。

三种处理，按你的情况选：

| 选择 | 操作 | 代价 |
|---|---|---|
| A. 做实验这几周先关掉 | `wsl --shutdown` → `bcdedit /set hypervisorlaunchtype off` → 重启 | WSL2 / Docker Desktop 暂时不能用；恢复用 `bcdedit /set hypervisorlaunchtype auto` |
| B. 只关"内核隔离" | Windows 安全中心 → 设备安全性 → 内核隔离 → **内存完整性：关** → 重启 | 基本无感，强烈建议 |
| C. 就这么用 | 不改 | 慢，但功能不缺；流量不大时演示够用 |

#### 2.3.2 虚拟网络：四种模式怎么选

| 模式 | 行为 | 实验里的用途 |
|---|---|---|
| NAT（VMnet8） | VM 借主机上网，主机能访问 VM，VM 之间互通 | 装系统、`apt`、查资料 |
| **仅主机（VMnet1）** | 只在主机和同网段 VM 之间通信，不碰物理网卡 | **实验主网段（推荐）** |
| 桥接（VMnet0） | 直接接物理网卡，和校园网同网段 | 想抓"真实网络"流量；有线比 Wi-Fi 靠谱 |
| LAN 段 | 完全私有的虚拟交换机，主机也进不去 | 想彻底隔离、不影响主机网络 |

推荐拓扑（三台机器一台主机，全在一台物理机上）：

```
             Windows 主机
        10.10.10.1 (VMnet1)
                 │
        ┌────────┴─────────┐
   sniffer            victim          server(可选)
 10.10.10.10        10.10.10.20       10.10.10.30
   Ubuntu Desktop    Ubuntu Desktop    Ubuntu Server
        └──── 另各挂一块 NAT 网卡，用于 apt ────┘
```

**改网段**：`编辑 → 虚拟网络编辑器`（需要管理员）→ 选中 VMnet1 → 把子网 IP 改成 `10.10.10.0`、掩码 `255.255.255.0` → 应用。默认的 `192.168.x.0` 很容易和宿舍/教室网络撞车。

改完之后主机上会多出一块 `VMware Network Adapter VMnet1`，地址是 `10.10.10.1`——**它顺手就成了"服务器"角色**，可以直接从 Windows 往 VM 发流量，不用再开第三台。

> 关于混杂模式：VMware 没有 VirtualBox 那个「Allow All」勾选框，guest 请求混杂模式时默认是放行的。但**能不能看到"另外两台 VM 之间"的单播流量，取决于虚拟交换机的转发策略，必须实测**（见 2.3.6 第 3 条）。看不到也不要慌：那是交换式网络的正常行为，报告里正好可以写；真正的 MITM 演示靠 ARP 欺骗，包是发给你的 MAC 的，根本不需要混杂模式。

#### 2.3.3 建虚拟机

1. `新建虚拟机 → 典型 → 稍后安装操作系统`（先建空机再挂 ISO，避免"简易安装"改坏配置）。
2. 客户机系统：Linux → Ubuntu 64 位。名称 `sniffer`，路径**不要有中文和空格**，放 SSD。
3. 磁盘 25 GB，选"拆分成多个文件"（方便拷贝、挂载）。
4. 自定义硬件：
   - 内存 4096 MB（宿主 16 GB 可给 6144）
   - 处理器 2 核；"虚拟化 Intel VT-x/EPT" **不用勾**（那是给嵌套虚拟化用的）
   - 显示器：**取消"加速 3D 图形"**——Qt 界面在软件渲染下更稳，少一类花屏
   - 声卡、打印机：移除
   - 网络适配器：`NAT`
   - `添加 → 网络适配器 → 自定义 → VMnet1`
5. 挂 Ubuntu 22.04.x / 24.04.x **Desktop** ISO，启动安装：
   - 选"最小安装"，不勾"安装第三方驱动"
   - 用户名用**小写英文**（后面路径、命令行都要用）
   - 安装时下载更新可以跳过，装完统一 `apt upgrade`

#### 2.3.4 装完的十分钟配置

```bash
sudo apt update && sudo apt install -y build-essential git cmake libpcap-dev tcpdump python3-pyqt5
sudo systemctl enable --now open-vm-tools      # 剪贴板、拖拽、分辨率自适应
ip -br a                                       # 认网卡名：一般 ens33=NAT，ens37=VMnet1
```

配静态 IP（Desktop 上用 nmcli 最省事）：

```bash
nmcli con show                                  # 看第二块网卡的连接名，通常 "Wired connection 2"
sudo nmcli con mod "Wired connection 2" ipv4.method manual ipv4.addresses 10.10.10.10/24
sudo nmcli con up "Wired connection 2"
ping -c 2 10.10.10.1                            # 能通到主机 VMnet1
```

Server 版用 netplan（`/etc/netplan/01-lab.yaml`）：

```yaml
network:
  version: 2
  ethernets:
    ens37:
      dhcp4: false
      addresses: [10.10.10.20/24]
```

```bash
sudo netplan apply
```

然后 **VM → 快照 → 拍摄快照**，命名 `01-clean`。之后每到一个里程碑拍一张（`02-deps`、`03-demo-ready`）。实验炸了 10 秒回滚，这是虚拟机相对 WSL2 最大的优势。

#### 2.3.5 第二、第三台：用克隆，别重装

`VM → 管理 → 克隆 → 完整克隆`（**不要链接克隆**，父机一删子机就废）。

- `victim`：10.10.10.20
- `server`（可选）：10.10.10.30

克隆后立刻改三样，否则主机名、DHCP 标识、日志都会串：

```bash
sudo hostnamectl set-hostname victim
sudo truncate -s 0 /etc/machine-id && sudo systemd-machine-id-setup
sudo nmcli con mod "Wired connection 2" ipv4.addresses 10.10.10.20/24 && sudo nmcli con up "Wired connection 2"
```

#### 2.3.6 十分钟验证（别跳过）

1. **互通**：victim `ping 10.10.10.10` 通，sniffer `ping 10.10.10.20` 通。
2. **抓到自己**：sniffer 上 `sudo tcpdump -i ens37 -n icmp`，victim 去 ping 它 → 必须看到 4 个包。
3. **抓到第三方**（关键实验）：让 victim `ping 10.10.10.30`（server），sniffer 上：

   ```bash
   sudo tcpdump -i ens37 -n -e icmp
   ```

   - 看得到 → 虚拟交换机把帧也转给了你，混杂模式有效，演示可以更漂亮；
   - 看不到 → **正常**，这就是交换式网络；改用 ARP 欺骗（5.7 节）。
4. **确认是否真的进了混杂模式**：`ip link show ens37` 输出里要有 `PROMISC`。
5. **抓包权限**：`sudo setcap cap_net_raw,cap_net_admin=eip $(readlink -f $(which python3))`，之后 GUI 不用 sudo 也能跑（仅限实验虚拟机）。

#### 2.3.7 用 VirtualBox 的对照

如果你某天换 VirtualBox：把第 2 块网卡设成「内部网络 `labnet`」，并在网卡高级里选「混杂模式 = 全部允许」，其余步骤（静态 IP、克隆、快照、验证）完全一样。

## 3. 从哪入手：用"验收"倒推实现

新手最常见的错误是上来就搭 Qt 界面，三天后界面很漂亮但一个包都没抓到。正确顺序是**先定义演示，再定义功能，最后才是界面**。

### 3.1 第一步：写下视频里必须出现的 8 个画面

把这张表抄进报告的需求分析一节，后面所有开发都围绕它：

| # | 画面 | 对应能力 |
|---|---|---|
| 1 | 启动程序，下拉框里能看到 `eth0/eth1/lo` | 网卡枚举 `pcap_findalldevs` |
| 2 | 选网卡 → 开始 → 列表疯狂滚动 | 抓包线程 + 列表模型 |
| 3 | 在过滤框输入 `tcp port 80`，回车后只剩 HTTP | BPF 过滤 |
| 4 | 点一个包，下方出现协议树（以太网/IP/TCP/HTTP） | 逐层解析 |
| 5 | 下方的十六进制区随选中包变化 | 原始字节视图 |
| 6 | 切到"流追踪"，看到 `10.0.0.5:49876 → 93.184.216.34:80` 这条流 | 五元组聚合 |
| 7 | 另一台 VM `ping` 本机，本机抓到 ICMP；开启混杂后抓到**两台别的机器**之间的包 | 混杂模式 / 抓包范围 |
| 8 | 停止 → 保存 pcap → 用 Wireshark 打开，包数一致 | 落盘与互操作 |

第 7 条是"讲清楚原理"的关键，也是很多人做不出来的地方（见 5.7）。

### 3.2 第二步：20 行冒烟程序（先证明环境是通的）

C 版本，这是整个实验的地基：

```c
#include <pcap.h>
#include <stdio.h>

int main(int argc, char **argv) {
    char errbuf[PCAP_ERRBUF_SIZE];
    pcap_t *h = pcap_open_live(argv[1], 65535, 1 /*promisc*/, 1000, errbuf);
    if (!h) { fprintf(stderr, "open: %s\n", errbuf); return 1; }

    struct pcap_pkthdr *hdr;
    const u_char *pkt;
    int n = 0;
    while (pcap_next_ex(h, &hdr, &pkt) >= 0 && n++ < 10) {
        printf("%ld.%06ld  caplen=%u  len=%u\n",
               (long)hdr->ts.tv_sec, (long)hdr->ts.tv_usec, hdr->caplen, hdr->len);
    }
    pcap_close(h);
    return 0;
}
```

```bash
gcc -O2 -o sniff sniff.c -lpcap
sudo ./sniff eth0
# 另开终端： ping -c 3 8.8.8.8
```

能看到 10 行输出、并且 `ping` 的 ICMP 包出现在里面，环境就算通了。**这一步不通过，后面全是空转。**

Python 版本（本仓库已实现，见 `sniffer/pcap.py`）：

```python
from sniffer.pcap import Capture
cap = Capture("eth0")
for _ in range(10):
    rec = cap.next_packet()
    if rec:
        ts, caplen, wirelen, data = rec
        print(f"{ts:.6f} {caplen} {wirelen} {data[:14].hex()}")
cap.close()
```

### 3.3 第三步：解析器（NPA 的主体）

按层写，一层一个函数，**任何字段越界都不许抛异常**——抓包程序最怕一个畸形包把线程搞崩：

```
parse_ethernet → (VLAN 循环) → parse_ipv4 / parse_ipv6 → parse_tcp / parse_udp / parse_icmp → 应用层初判
```

IPv6 记得跳过扩展头（逐跳 0、路由 43、目的选项 60、AH 51、分片 44），否则你会把扩展头当成 TCP 头，端口解析出天文数字。

### 3.4 第四步：命令行跑通，再上 GUI

先用 CLI 验证"抓包 → 解析 → 打印"这条链路（`sniffer/cli.py`），确认没问题再加界面。GUI 只做三件事：**把 Packet 塞进表格模型、把选中的 Packet 渲染成树和十六进制、把过滤表达式交给引擎**。

### 3.5 第五步：过滤与流

过滤一律走 libpcap（`pcap_compile` + `pcap_setfilter`），不要自己写字符串匹配——文档 p14 明确说"libpcap 提供了数据包筛选功能"，这是要考的点。

## 4. 总体架构

```
┌──────────────────────────── GUI 主线程 (Qt) ────────────────────────────┐
│  工具栏：网卡下拉 / 过滤输入框 / 开始停止 / 保存                        │
│  包列表 QTableView ← PacketModel                                        │
│  详情树 QTreeWidget + 十六进制 QPlainTextEdit                           │
│  流追踪 QTableView ← FlowModel                                          │
│  QTimer(60ms)：从队列批量取包 → 插模型（一次 4000 条，避免逐条刷新）    │
└───────────────────────────────▲────────────────────────────────────────┘
                                │ Queue<Packet>（线程安全，满了就计数丢弃）
┌───────────────────────────────┴────────────────────────────────────────┐
│  抓包线程 CaptureEngine                                                 │
│    pcap_next_ex ──► decode.parse ──► FlowTable.feed ──► 入队            │
│                    └─► 可选：pcap_dump 落盘                            │
└───────────────────────────────▲────────────────────────────────────────┘
                                │ BPF（内核态过滤，pcap_setfilter）
                        libpcap / Npcap
                                │
                          AF_PACKET 套接字
```

模块与职责：

| 模块 | 职责 | 关键 API |
|---|---|---|
| `pcap.py` | libpcap 生命周期、设备枚举、过滤、落盘 | `pcap_findalldevs` `pcap_create` `pcap_activate` `pcap_compile` `pcap_next_ex` `pcap_dump` |
| `decode.py` | 逐层解析、摘要、详情行、hexdump | 纯字节处理 |
| `flows.py` | 五元组聚合、状态、进程归因 | `/proc/net/tcp` + `/proc/*/fd` |
| `engine.py` | 线程、队列、统计、启停 | `std::thread` / `threading.Thread` |
| `cli.py` / `gui.py` | 展示层 | Qt Model/View |

**线程模型只有一句话**：`pcap_next_ex` 是阻塞的（默认超时 100 ms），绝不能放在 GUI 主线程；抓包线程只做"读 + 解析 + 入队"，界面线程只做"出队 + 渲染"。

## 5. 关键技术点

### 5.1 libpcap 打开设备的顺序

```c
pcap_t *h = pcap_create(dev, errbuf);
pcap_set_snaplen(h, 262144);        // 抓多长：太小会截断大包
pcap_set_promisc(h, 1);             // 混杂模式
pcap_set_timeout(h, 100);           // 毫秒，影响 next_ex 的返回粒度
pcap_set_buffer_size(h, 32<<20);    // 内核缓冲，32MB，直接影响丢包
pcap_activate(h);
```

不要用 `pcap_open_live` 一把梭——它不能设置缓冲区大小，高流量下必丢包。

参数怎么解释（报告里可以直接用）：

- **snaplen**：每个包最多拷贝多少字节。设 262144 能完整抓下 jumbo frame；设 96 就只留头部，省内存但看不到载荷。
- **promisc**：让网卡接收所有经过它的帧，而不只是发给自己的。**但交换式网络里"经过它的帧"本来就很少**，见 5.7。
- **timeout**：`pcap_next_ex` 的阻塞上限。太小 CPU 空转，太大界面卡顿（用线程时影响的是延迟）。
- **buffer_size**：内核环形缓冲。抓包丢包 90% 是这里太小。

### 5.2 BPF 过滤

```c
struct bpf_program prog;
pcap_compile(h, &prog, "tcp port 80 and host 192.168.56.20", 1, PCAP_NETMASK_UNKNOWN);
pcap_setfilter(h, &prog);
pcap_freecode(&prog);       // 编译结果已经进内核，用户态这份可以释放
```

常用表达式：

```
tcp / udp / icmp / arp
port 80 / portrange 8000-8100
host 192.168.56.20 / net 192.168.56.0/24
ip6 / icmp6
tcp[tcpflags] & tcp-syn != 0          # 只抓 SYN
http                                   # 需要 libpcap 认识 http 关键字（部分版本没有）
not port 22
```

**为什么必须在内核过滤**：BPF 程序挂在 socket 上，内核在把包交给用户态之前就丢掉不匹配的，CPU 和内存开销都在内核侧。全抓上来再在 Python/C++ 里 `if` 过滤，等于把"高速公路上设卡"改成"下高速后一个个查"，流量一大就丢包——这正是文档 p21–25 在讲的事。

### 5.3 解析要点

- **以太网**：目的/源 MAC + 类型；`0x8100/0x88a8` 是 VLAN，可能多层（QinQ），要循环剥。
- **IPv4**：`ihl` 决定头长（可能带选项），`total_len` 才是真实长度；`MF/片偏移` 非零说明是分片，**后续层不可解析**，要单独标记。
- **IPv6**：固定 40 字节头 + 扩展头链，`next_header` 要一路走到 6/17/58 才是 TCP/UDP/ICMPv6。
- **TCP**：`data offset` 决定头长（20–60，带选项）；标志位逐位判断；`payload = data[off+hdr_len:]`。
- **应用层初判**：端口只是线索，不是证据。HTTP 看首行是不是方法或 `HTTP/`；TLS 看 `0x16 0x03`；DNS 看 53 端口 + 能否解析出域名。**文档 p9 的思考题"如何识别某种特定类型的应用层报文"，答案就写在这里。**

### 5.4 GUI 与线程

- 抓包线程里**不要碰任何控件**。Qt 跨线程只认 signal/slot（队列连接）或你自己的 Queue + 定时器；本仓库用后者，简单且不会被 Qt 的对象亲和性坑。
- 不要来一个包 `append` 一行——10 万包会把界面拖死。**批量入队、批量插入**（一次 2000–4000 条）。
- 详情树和十六进制**只在选中时渲染**，不要每来一个包就格式化一遍。
- 表格行数设上限（如 20 万行），超出丢最老的，否则内存会爬到你怀疑内存泄漏。

### 5.5 流追踪（加分项）

- key 用**规范化五元组**：`(proto, min((ip,port)), max((ip,port)))`，否则 A→B 和 B→A 会变成两条流。
- 方向由第一个纯 SYN 决定谁是客户端；之后同 key 的包都归到这条流。
- 流表用 LRU（`OrderedDict` 或 `std::list + unordered_map`），超过 2 万条淘汰最久未用的。
- 统计：包数、字节数、双向字节、持续时间、TCP 状态（SYN/FIN/RST）、应用层协议与 Host/SNI。
- **按进程归因**（文档里的进阶要求）：`/proc/net/tcp` 里每一行有 socket inode → 遍历 `/proc/<pid>/fd/*` 找 `socket:[inode]` → 得到 pid 和进程名。需要 root 才能看全。

### 5.6 性能与丢包

报告里能写、演示时能秀的三件事：

1. 显示 `pcap_stats()` 的 `ps_recv / ps_drop`，让老师看到你**知道会丢包**并量化了。
2. 说明 snaplen、buffer_size、BPF 三个旋钮如何影响丢包。
3. 提到 `TPACKET_V3`、`PF_RING`、`eBPF/XDP`（文档 p23–24 的 ChatGPT 答案就是素材），并说清"本实验为什么不需要"。

### 5.7 抓包范围：为什么你只能抓到自己（重点，答辩必问）

```
   主机A ──┐
           ├── 交换机 ── 路由器
   主机B ──┘
```

交换机按 MAC 表转发，**A→B 的单播帧根本不会送到 C 的网卡**。所以在 C 上开混杂模式也抓不到 A、B 的对话，只能抓到：广播（ARP）、组播、以及发给 C 自己的包。

要抓到别人的流量，只有三条路：

1. **端口镜像**（交换机上配置 SPAN）——实验室没有。
2. **ARP 欺骗**：C 不断告诉 A"网关的 MAC 是我"，告诉网关"A 的 IP 在 C 这里"，于是 A→网关的流量先到 C，C 转发出去（`ip_forward=1`），这就是中间人。**这也是"嗅探器 + 安全"的结合点，报告里值得单独一节。**
3. **集线器/虚拟交换机**：VirtualBox 的「内部网络」本质是虚拟 hub，配合混杂模式=全部允许，就能看到同网段所有帧——**这正是我们选虚拟机做实验的原因**。

> 演示 ARP 欺骗的顺序：先 `ping` 通 → 开 `ip_forward` → 发 ARP 欺骗 → 在嗅探器里看到受害者与网关之间的流量 → 停止欺骗、恢复 ARP 表。**每一步都要能解释"为什么"。**

HTTPS 同理：没有中间人证书，你只能看到 SNI 和证书链，看不到明文。文档 p14 的 Thor 思考题（装了根证书就能解 HTTPS，但某些传输层内容仍然无能为力）说的就是这件事：**"能抓到"和"能看懂"是两回事，取决于你有没有信任链上的位置。**

## 9. 常见坑

1. **`pcap_open_live` 返回 NULL**：没权限（用 sudo 或 `setcap cap_net_raw,cap_net_admin=eip`）、网卡名写错（`eth0` 在新版 Ubuntu 上叫 `ens33`/`enp0s3`）。
2. **抓不到任何包**：选错网卡（VM 有两块，要选 `labnet` 那块）；或过滤表达式把包全滤掉了。
3. **只能抓到自己**：交换机/NAT 的锅，不是代码的锅——见 5.7。
4. **混杂模式无效**：VirtualBox 网卡高级设置里没选「全部允许」。
5. **校验和全是错的**：虚拟网卡的 checksum offload，包在抓取时还没算校验和。报告里说明即可，不要试图"修"。
6. **大包被截断**：snaplen 太小；或网卡开了 TSO/GSO，抓到的是超大段。
7. **界面卡死**：在 GUI 线程里调了 `pcap_next_ex`，或者逐包刷新表格。
8. **内存暴涨**：包列表无上限、每条流缓存了全部载荷。
9. **IPv6 端口离谱**：没跳过扩展头。
10. **中文乱码**：源码文件用 UTF-8；Qt 里设置字体；终端 `LANG=zh_CN.UTF-8`。
11. **判卷机跑不起来**：依赖没写进文档、用了绝对路径、Python 版本不一致。**在干净快照里从零走一遍文档步骤。**
12. **Git 只有一个 commit**：平时就要提交，别最后一次性 push——文档明确要求"完整记录"。
